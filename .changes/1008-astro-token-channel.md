### Fixed

- **`@reticlehq/init` — Astro 7.2+ gets the pairing token through frontmatter, not `vite.define`.** On current Astro, `vite.define` does not reach the client pipeline, so `__RETICLE_TOKEN__` stayed literal, `connect()` omitted `token`, and the bridge refused with "no pairing token on the page". `init` now reads the file in frontmatter, puts it on a `<meta name="reticle-pairing-token">`, and connects from a local module with a static SDK import (a bare `await import('@reticlehq/react')` from a page script 404s while Vite's dep cache is cold). The example, which already has `@astrojs/react`, mounts a dev-only React island that reads the same meta tags. The example moves off the 7.0.3 pin. [#1008](https://github.com/reticlehq/reticle/issues/1008).
